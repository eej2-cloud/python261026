# To-do List 웹사이트 TRD

## 1. 기술 구성

- HTML5: 문서 구조와 접근성 있는 입력/목록 컨트롤
- CSS3: 레이아웃, 반응형 스타일, 완료 상태 및 포커스 표시
- Vanilla JavaScript (ES6+): 상태 관리, 이벤트 처리, 렌더링, 저장소 연동
- 데이터 저장: 브라우저 `localStorage`
- 프레임워크, 빌드 도구, 서버: MVP에서는 사용하지 않음

## 2. 디렉터리 구조

```text
todolist/
├── index.html
├── css/
│   └── styles.css
├── js/
│   └── app.js
├── prd.md
├── trd.md
└── task.md
```

위 구조는 구현 시 사용할 제안 구조이며, 현재 단계에서는 문서만 작성한다.

## 3. 데이터 모델

할 일은 다음 필드를 갖는 객체로 관리한다.

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | 문자열 | 항목을 식별하는 고유 ID |
| `text` | 문자열 | 사용자가 입력한 할 일 내용 |
| `completed` | 불리언 | 완료 여부 |
| `createdAt` | 문자열 | 생성 시각의 ISO 8601 값 |

저장 키는 `todolist.items`를 사용한다. 저장 값은 할 일 객체 배열을 JSON으로 직렬화한다.

## 4. 동작 설계

- 페이지 초기화 시 저장된 JSON을 읽고 형식을 확인한 뒤 화면을 그린다.
- 데이터가 없으면 빈 배열로 시작한다.
- 저장 데이터가 파싱 불가능하거나 기대한 구조가 아니면 사용자에게 복구 안내를 제공하고 안전한 빈 목록으로 시작한다. 기존 손상 데이터는 별도 처리 없이 덮어쓰지 않도록 한다.
- 추가, 완료 상태 변경, 삭제 시 상태를 갱신하고 저장한 다음 화면을 갱신한다.
- 필터 상태는 화면 표시만 제어하며 원본 목록을 변경하지 않는다.
- 사용자 입력은 HTML로 해석하지 않고 텍스트로 표시해 임의의 마크업 실행을 방지한다.
- 저장소 접근/쓰기 오류를 사용자에게 알리고, 성공한 것처럼 조용히 처리하지 않는다.

## 5. 화면 및 접근성

- 시맨틱 요소와 명시적인 레이블을 사용한다.
- 버튼과 체크 컨트롤은 키보드로 접근 가능해야 한다.
- 포커스 표시와 완료 상태를 색상만으로 전달하지 않는다.
- 모바일 화면에서 목록, 입력, 필터가 가로 넘침 없이 배치되도록 한다.
- 동적으로 갱신되는 목록/안내는 스크린 리더가 변화를 인지할 수 있도록 적절한 라이브 영역을 고려한다.

## 6. 브라우저 및 실행

- 최신 주요 브라우저(Chrome, Edge, Firefox, Safari)의 기본 기능을 대상으로 한다.
- 정적 파일로 로컬에서 실행 가능하도록 구성한다.
- `localStorage` 사용을 위해 브라우저의 일반적인 웹 출처에서 실행한다. 일부 브라우저의 `file://` 동작 차이는 구현 및 테스트 시 확인한다.

## 7. 품질 및 검증

- 기능 확인: 추가, 빈 입력 방지, 완료 토글, 삭제, 필터링, 새로고침 후 복원
- 예외 확인: 손상된 저장 데이터, 저장소 사용 불가/쓰기 실패
- 반응형 확인: 좁은 모바일 너비와 데스크톱 너비
- 접근성 확인: 키보드만으로 주요 흐름 수행, 포커스 표시, 레이블과 상태 안내 확인
- 개발자 도구 콘솔에 처리되지 않은 오류가 없어야 한다.
