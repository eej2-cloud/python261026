# To-do List 웹사이트 PRD

## 1. 제품 개요

HTML5, CSS3, JavaScript를 사용해 개인 작업을 간단히 기록하고 관리하는 반응형 To-do List 웹사이트를 만든다. 별도의 서버나 계정 없이 브라우저에서 바로 사용할 수 있는 MVP를 목표로 한다.

## 2. 목표와 성공 기준

- 사용자가 할 일을 빠르게 추가하고 완료 상태를 관리할 수 있다.
- 새로고침하거나 브라우저를 다시 열어도 할 일 목록이 유지된다.
- 데스크톱과 모바일 화면에서 주요 기능을 불편 없이 사용할 수 있다.
- 핵심 흐름을 마우스와 키보드로 사용할 수 있다.

## 3. 대상 사용자

- 하루 또는 주간 할 일을 개인적으로 정리하고 싶은 사용자
- 회원가입이나 별도 앱 설치 없이 간단한 목록을 원하는 사용자

## 4. MVP 기능 범위

### 필수 기능

1. 할 일 추가
   - 입력란에 내용을 작성해 추가한다.
   - 빈 문자열 또는 공백만 입력한 항목은 추가하지 않는다.
   - Enter 키와 추가 버튼으로 등록할 수 있다.
2. 할 일 목록 표시
   - 저장된 항목을 목록으로 보여준다.
   - 항목별로 완료 여부와 할 일 내용을 표시한다.
3. 완료 상태 변경
   - 체크 컨트롤을 통해 미완료와 완료 상태를 전환한다.
   - 완료 항목은 시각적으로 구분한다.
4. 할 일 삭제
   - 항목별 삭제 기능을 제공한다.
5. 목록 필터
   - 전체, 진행 중, 완료 항목을 구분해 볼 수 있다.
6. 데이터 유지
   - 브라우저의 `localStorage`에 목록을 저장하고 다시 불러온다.
7. 사용성 및 접근성
   - 입력, 체크, 삭제, 필터 컨트롤에 명확한 이름을 제공한다.
   - 키보드로 주요 기능을 사용할 수 있고 포커스 상태를 표시한다.
   - 목록이 비어 있을 때 안내 문구를 표시한다.

### 제외 범위

- 회원가입, 로그인, 서버 동기화
- 여러 목록/프로젝트 관리
- 마감일, 우선순위, 태그, 반복 일정
- 알림, 공유, 협업 기능
- 외부 라이브러리 및 프레임워크 도입

## 5. 사용자 흐름

1. 사용자가 페이지를 연다.
2. 입력란에 할 일을 입력하고 Enter 또는 추가 버튼을 누른다.
3. 목록에서 할 일의 완료 상태를 변경하거나 삭제한다.
4. 필요하면 전체/진행 중/완료 필터를 선택한다.
5. 페이지를 다시 열어도 이전 목록을 확인한다.

## 6. 요구사항 및 수용 기준

- 유효한 할 일은 목록에 즉시 나타나며 저장된다.
- 빈 입력은 목록에 추가되지 않는다.
- 완료 상태 변경은 화면과 저장 데이터에 모두 반영된다.
- 삭제한 항목은 화면과 저장 데이터에서 제거된다.
- 각 필터는 해당 상태의 항목만 표시하며 전체 필터는 모두 표시한다.
- 새로고침 후에도 목록과 완료 상태가 유지된다.
- 모바일 너비에서도 입력란과 주요 컨트롤을 사용할 수 있다.
- 데이터가 없을 때 빈 목록 안내가 표시된다.

## 7. 제품 가정

- 목록은 현재 브라우저와 현재 출처에 저장되며 다른 기기와 공유되지 않는다.
- 저장 용량 초과나 저장소 접근 오류는 조용히 무시하지 않고 사용자에게 안내한다.
- MVP는 단일 사용자의 단일 목록을 대상으로 한다.

## 8. 향후 고려 사항

- 마감일 및 우선순위
- 목록 내 검색 및 정렬
- 데이터 내보내기/가져오기
- 서버 기반 계정 및 기기 간 동기화
